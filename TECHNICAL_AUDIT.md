## 1. Что это за проект СЕЙЧАС

**AIR4** — локальный однопользовательский чат-ассистент с векторной памятью (RAG) и базовой системой фактов.

**Архитектура:**
- **Backend:** FastAPI (Python), локальный сервер на `127.0.0.1:8000`
- **Frontend:** React (TypeScript) в `backend/app/static/googleui/`, доступ через `/ui/google` → `/static/googleui/dist/index.html`
- **Memory:** ChromaDB (векторная БД) в `./data/chroma` или `./storage/chroma`
- **LLM:** Ollama (локальные модели: llama3.1:8b, mistral, deepseek-r1 и др.)
- **Embeddings:** Sentence Transformers (all-MiniLM-L6-v2 или bge-m3)

**Тип:** Прототип/ядро. Однопользовательский (hardcoded `user_id="dev"`), локальный (нет сетевого доступа по умолчанию).

## 2. Backend — что РЕАЛЬНО РАБОТАЕТ

### API эндпоинты

**Chat:**
- `POST /chat` — основной чат-эндпоинт (routes_chat.py)
- `POST /send3` — упрощённый чат (main.py)
- `POST /chat/stream` — стриминг (routes_stream.py)

**Memory:**
- `GET /memory/search` — поиск по векторной памяти
- `POST /memory/add` — добавление заметок
- `GET /memory/debug` — диагностика памяти
- `GET /memory/debug/query_raw` — прямой запрос к Chroma

**Facts (Knowledge Graph):**
- `GET /facts` — список фактов (subject="Arch")
- `GET /facts/profile` — структурированный профиль
- `POST /facts/reindex` — переиндексация фактов в память
- `DELETE /facts/wipe` — удаление всех фактов для subject
- `DELETE /facts/purge` — удаление по фильтрам

**Ingest (загрузка файлов):**
- `POST /ingest/file` — загрузка файла → inbox → commit → process
- `POST /ingest/url` — загрузка URL
- `POST /ingest/process` — обработка очереди из `data/ingest/store/queue.json`
- `GET /ingest/status` — статус inbox
- `GET /ingest/queue` — очередь на обработку
- `GET /ingest/preview` — предпросмотр файла (TXT/PDF/DOCX)
- `POST /ingest/commit` — коммит файла из inbox в store (SHA256 дедупликация)
- `POST /ingest/commit-all` — коммит всех файлов
- `DELETE /ingest/clear` — очистка inbox

**Sessions:**
- `GET /sessions` — список сессий
- `POST /sessions` — создание сессии
- `GET /sessions/{session_id}` — получение сессии с сообщениями
- `POST /sessions/{session_id}/clear` — очистка сессии

**Profile:**
- `GET /memory/profile` — профиль пользователя (JSON)
- `PATCH /memory/profile` — обновление профиля
- `PUT /memory/profile` — полная замена профиля

**Models:**
- `GET /models` — список доступных моделей Ollama

**Health:**
- `GET /health` — статус системы

**UI Routes (HTML):**
- `GET /` → редирект на `/ui/chat`
- `GET /ui/chat` — чат-интерфейс
- `GET /ui/ingest` — интерфейс загрузки
- `GET /ui/sessions` — список сессий (HTMX)
- `GET /ui/summary` — саммари (заглушка)
- `GET /ui/settings` — настройки
- `GET /ui/google` → `/static/googleui/dist/index.html` (React UI)

### Chat (/chat)

**Статус:** ✔️ реализовано и используется

**Функции:**
- Интеграция с Ollama (локальные LLM)
- RAG: поиск по памяти перед ответом (строгий режим, threshold 0.60)
- Автоизвлечение профильных фактов (локация, работа, знак зодиака, цели, тренировки)
- Обработка специальных команд (#morning_check, #evening_check, #week_check)
- Сохранение сообщений в JSONL (`data/sessions/{session_id}.jsonl`)
- Поддержка стилей ответа (short/normal/detailed)
- Выбор модели из UI
- Small talk детекция (без RAG для коротких фраз)

**Ограничения:**
- `ENABLE_CHAT_MEMORY = False` в main.py — сообщения чата НЕ сохраняются в векторную память автоматически
- Только факты и документы попадают в память

### Memory

**Статус:** ✔️ реализовано и используется

**Backend:** ChromaDB (ChromaMemoryManager)
- Путь: `AIR4_CHROMA_DIR` (по умолчанию `./data/chroma`)
- Коллекция: `AIR4_CHROMA_COLLECTION` (по умолчанию `"air4"`)
- Embeddings: `AIR4_EMBED_MODEL_PATH` или `all-MiniLM-L6-v2`
- Fallback: InMemoryMemoryAdapter (если Chroma не инициализируется)

**Неймспейсы памяти:**
- `facts` — факты из Knowledge Graph (facts_store.json)
- `docs` — документы из ingest (meta.kind="file")
- `sessions` — саммари сессий (если включены)
- `note` — ручные заметки через `/memory/add`

**Метаданные:**
- `user_id` — всегда "dev" (hardcoded)
- `session_id` — ID сессии чата
- `source` — источник (user/assistant/ingest/facts/summary)
- `kind` — тип (file/note/fact)
- `tag` — тег для фильтрации
- `created_at` — timestamp

**Поиск:**
- Векторный поиск (cosine similarity)
- Score threshold: 0.2 (настраивается)
- Deduplication по тексту
- Фильтрация по `where_json` (например, `{"kind": "file"}`)

### RAG / поиск по документам

**Статус:** ✔️ реализовано и используется

**Реализация:**
- Интеграция в `/chat` и `/send3`
- Поиск через `/memory/search` с фильтром `{"kind": "file"}` (только документы)
- Контекст подмешивается в system prompt
- Строгий режим: если RAG-контекст есть, модель должна отвечать только на его основе

**Ограничения:**
- RAG отключён для small talk (фразы < 40 символов)
- Score threshold 0.60 (строгий режим в routes_chat.py)

### Ingest файлов

**Статус:** ✔️ реализовано и используется

**Поддерживаемые форматы:**
- TXT, MD, LOG, CSV — текстовые файлы
- PDF — через PyPDF2 (первые 5 страниц в preview)
- DOCX — через python-docx
- URL — простой fetch (HTML/PDF)

**Процесс:**
1. Загрузка → `data/ingest/inbox/`
2. Commit → `data/ingest/store/` с SHA256 дедупликацией
3. Process → извлечение текста и добавление в ChromaDB через `ingest_path()`

**Очередь:**
- `data/ingest/store/queue.json` — список файлов на обработку
- `POST /ingest/process` — обработка очереди

**Что работает:**
- Chat, Ingest, Memory — основные экраны
- Settings, Sessions

**Что мешает назвать это v1.0:**
- Нет Search UI
- Нет Todos UI
- Delete memory не работает (нет backend)
- Двойное хранение сессий (localStorage + сервер)

### Готовность продукта AIR4 в целом: **60%**

**Что мешает назвать это v1.0:**
1. **Security не активен** — нет реальной защиты данных
2. **Только один пользователь** — нет мультипользовательской системы
3. **Нет автоматизации** — саммари, автообновление фактов не работают
4. **Неполная интеграция** — некоторые UI функции не имеют backend
5. **Нет шифрования** — все данные в plain text

**Критичные вещи до MVP:**
1. **Подключить Security** — активировать RBAC middleware, хотя бы базовую аутентификацию
2. **Исправить Delete Memory** — добавить `DELETE /memory/delete` эндпоинт
3. **Убрать hardcoded user_id** — хотя бы параметризовать, если не делать мультипользовательскую систему
4. **Автоматизация саммари** — вызывать summarizer после сессий или добавить ручной триггер
5. **Единое хранение сессий** — убрать дублирование localStorage + сервер

## 7. Финальный вывод

### Чем AIR4 уже ЯВЛЯЕТСЯ по коду

**Локальный чат-ассистент с памятью:**
- Работающий чат с локальными LLM (Ollama)
- Векторная память (ChromaDB) для документов и фактов
- RAG для ответов на основе документов
- Knowledge Graph (факты) для профиля пользователя
- Загрузка файлов (PDF, TXT, DOCX) с индексацией
- Сессии чата с сохранением истории

**Прототип/ядро:**
- Базовая архитектура работает
- Основные функции реализованы
- UI функционален для основных сценариев

### Чем он ПОКА НЕ является

**Не является "менеджером жизни":**
- Нет менеджера задач (только код без UI)
- Нет автоматизации целей
- Нет автопилотов/агентов
- Нет интеграции с внешними сервисами

**Не является безопасной системой:**
- Security не подключён
- Нет шифрования данных
- Нет реальной аутентификации
- Duress mode не работает на backend

**Не является мультипользовательской системой:**
- Только один пользователь (hardcoded "dev")
- Нет разделения данных между пользователями

**Не является готовым продуктом:**
- Много незавершённых функций
- Нет автоматизации
- Неполная интеграция UI и backend

### Насколько текущая реализация соответствует идее

**"Локальный персональный интеллект / второй мозг / менеджер жизни"**

**Соответствие: ~40%**

**Что соответствует:**
- ✅ Локальный (всё работает локально, без облака)
- ✅ Персональный (для одного пользователя)
- ✅ Интеллект (чат с LLM, RAG, факты)
- ✅ Второй мозг (память документов, факты, профиль)

**Что НЕ соответствует:**
- ❌ Менеджер жизни (нет задач, целей, автоматизации)
- ❌ Безопасность (нет шифрования, security не активен)
- ❌ Автоматизация (нет автопилотов, саммари не работают)

**Вывод:**
AIR4 — это **рабочий прототип локального чат-ассистента с памятью**, но пока не полноценный "менеджер жизни". Основные функции (чат, память, факты, ingest) работают, но отсутствуют критичные компоненты (безопасность, автоматизация, задачи) для заявленной концепции.
